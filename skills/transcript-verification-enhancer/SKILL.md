**AI 에이전트 행동 지침**:
대화창에서 텍스트를 읽어와 수동으로 처리하지 말고, 내장 스크립트를 실행합니다. **단 순서를 지켜야 합니다** — 2026-08-27 검증에서 구버전 지침대로 실행하면 실제 전사본 36건 중 35건에서 즉시 실패하는 것이 확인됐습니다.

```bash
S=.agents/skills/transcript-verification-enhancer/scripts/batch_processor.py

# 1단계 — 구조를 먼저 확인한다 (읽기만, 쓰기 없음)
python $S <입력파일> --inspect

# 2단계 — LLM 없이 파이프라인만 돌려 무결성을 확인한다 (원문 유지 + change log)
python $S <입력파일> --out <출력경로> --dry-run

# 3단계 — 실제 정제. 외부 전송 사전 협의를 마친 경우에만
python $S <입력파일> --out <출력경로> --i-have-upload-approval
```

- **`--out`은 필수입니다.** 스크립트는 원본 옆에 자동 생성하지 않으며, native 경로로는 쓰지 않습니다(AGENTS.md §0).
- **`--sheet`·컬럼은 지정하지 않아도 됩니다.** 실측으로 찾습니다. 잘못 잡히면 `--inspect` 결과를 보고 `--text-col`로 교정합니다.
- **3단계는 사용자 승인 없이 실행하지 마십시오.** 아래 §외부 전송 참고.

# 전사 데이터 정확도 검증 & 퀄리티 향상 스킬

이 스킬은 STT(음성인식) 생성 전사본의 화자 오류, 도메인 오타, 파편화된 문단을 정제하고 가독성 및 정밀도를 향상시키는 역할을 수행합니다.

## 입력 및 대상
- 지원: `.xlsx` · `.xlsm` · `.csv`
- **`.xls` 미지원** — `xlrd`가 필요하고 현재 환경에 없습니다. `.xlsx`로 변환해 오십시오.
- **docx 미지원.** 다만 이 한계는 가볍지 않습니다 — `26.GP.UXQ` 전사본 8건이 docx이고, native에서 **화자 라벨이 제대로 정리된 유일한 케이스**입니다(`S1`~`S9` + `진행자`, #14 검증에서 확인). 즉 가장 처리하기 좋은 데이터가 대상 밖입니다. docx 경로 추가는 미착수 과제입니다.

### native 전사본 실제 구조 (2026-08-27 실측, xlsx 36건)

| 시트명 | 파일 수 |
|---|---|
| `Contents` | **35** |
| `1. 녹취 종합` | 1 — IBUJA **코딩 워크북**(전사본이 아님) |

`Contents`는 **헤더 행이 없습니다.** 1~3행이 제목·일시·참석자 메타이고 발화는 5행부터이며, 열 배치는 `[빈칸, 화자, 타임스탬프, 발화]`입니다. 컬럼 위치를 상수로 가정하면 깨집니다.

## 외부 전송 — 반드시 확인할 것

이 스크립트는 **전사본 원문을 외부 LLM API로 전송합니다**(litellm 경유). 내부 자료의 외부 전송은 사전 협의가 필요하므로, `--i-have-upload-approval` 없이는 스크립트가 LLM 호출을 **거부**합니다.

- 승인 없이 확인해야 할 때는 `--dry-run`을 씁니다. 구조·컬럼탐지·무결성·change log는 전부 확인되고 외부 호출만 빠집니다.
- 이 게이트를 우회하지 마십시오. 우회는 사용자 판단 사항입니다.

## 익명화는 이 스킬이 하지 않습니다

**익명화는 리서처가 직접 수행합니다**(2026-08-27 사용자 확정). 규칙은 [`익명화_공통규칙.md`](../../../익명화_공통규칙.md)에 있고, [`$transcript-anonymizer-skill`](../transcript-anonymizer-skill/SKILL.md)(#14)은 **치환이 아니라 잔존 검사**만 합니다. 이 스킬에서 인라인 치환하면 그 경계를 무너뜨립니다.

구버전 프롬프트에는 익명화 규칙이 복제돼 있었고 `P7 -> [P001]` 재치환까지 지시했는데, 이는 #14 검증에서 Critical로 잡힌 **이미 익명화된 라벨 재치환**입니다. 순서도 뒤집혀 있었습니다 — PII 포함 원문을 외부로 먼저 보내고 그 모델이 마스킹하는 구조였습니다.

**올바른 순서**: (1) 리서처가 `익명화_공통규칙.md`대로 직접 익명화 → (2) `#14`로 잔존 검사 → (3) 이 스킬로 정제. 외부 전송이 걸린 3단계는 익명화가 끝난 뒤여야 위험이 줄어듭니다.

## 절대 원칙: 원본 보존 및 원문 훼손 금지
- **원본 덮어쓰기 금지**: native repo의 원본 파일은 절대 수정하지 않습니다. 결과물은 `--out`으로 지정한 별도 파일로 생성하며, 스크립트가 native 경로 쓰기와 원본 덮어쓰기를 모두 차단합니다.
- **접미사는 프로젝트 관행을 따릅니다**: native 실측 `_가명화` 4건 vs `_cleaned` 1건 — **다수 관행은 `_가명화`** 입니다(`#14 A5`와 동일). `_cleaned`를 강제하지 않습니다.
- **행 구조를 바꾸지 않습니다**: 입력 행 수 = 출력 행 수. 구버전은 같은 화자의 연속 행을 병합하면서 `Context` 외 컬럼을 버렸고, IBUJA 코딩 워크북에서 `질문` 294셀 · `시간` 291셀 · `Code` 41셀(순감 35)이 삭제됐습니다. **`질문` 유실은 발화↔문항(question_id) 연결 절단**이고 `Code` 유실은 완료된 코딩 결과 소실입니다.
- **워크북을 통째로 보존합니다**: 원본을 열어 대상 셀만 갱신합니다. 구버전은 단일 시트로 새로 써서 7시트+차트1 → 1시트+차트0이 됐습니다.
- **수식 캐시 주의**: 수식은 보존되지만 openpyxl 저장 시 **계산 캐시값이 사라집니다**(실측: 수식 5,747셀 보존 / `data_only` 값 셀 16,542 → 10,811). Excel에서 한 번 열어 재계산하거나 값으로 고정한 뒤 하위 단계로 넘깁니다. 스크립트가 콘솔과 change log에 경고합니다.
- **원문 내용 손상 최소화**: 오타 교정, 화자 분리, 필어 제거를 수행하되, 인터뷰 참여자의 실제 발화 뉘앙스나 핵심 의미, 원문의 내용 자체를 AI가 임의로 왜곡·창작·과도하게 삭제하지 않고 최대한 원형을 보존해야 합니다.

## 정제 규칙 (파이프라인 단계)
1. **지시 대명사 지칭 대상 명확화 (`(괄호)` 보완)**:
   - 문맥상 "이거", "그거", "여기" 같은 지시대명사가 가리키는 실제 대상(화면명, 기능 등)을 유추하여 대명사 직후 `(괄호)` 안에 명시적으로 보완합니다.
   - 예: "여기서 그거 누르고..." → "여기`(하단 자산 탭)`서 그거`(연결 버튼)` 누르고..."

2. **화자 턴 정리 — 단, 행을 병합하지 않습니다**:
   - **문맥 전달 방식**: 인접 발화는 프롬프트의 `neighbors` 필드로 전달됩니다. 행을 실제로 합치지 않으므로 다른 컬럼(질문·시간·Code)이 보존됩니다.
   - 질문과 답변이 하나의 화자 라벨 아래에 뭉쳐있는 경우, 문맥을 파악해 `[진행자]`와 `[참여자]`의 독립된 턴으로 분리합니다.
   - 파편화된 단편 발화(예: 맞장구 "네", "음")는 동일 화자의 의미 문단으로 병합하여 가독성을 높입니다.

3. **STT 오인식 비문 & 도메인 어휘 교정**:
   - 금융/UX 도메인 어휘 오타를 교정합니다. (예: `호마면`→`홈화면`, `계좌체`→`계좌이체`, `키움정권`→`키움증권`).
   - 단, 참여자 성명의 음운 유사 오인식(예: `수연`→`수현`)이 의심될 경우, 임의로 수정하지 않고 리서처에게 선제 질의하여 확인을 받습니다.

4. **습관적 불필요 필어(Filler Words) 자동 정제**:
   - 본문 의미 전달에 기여하지 않는 구어체 추임새(`음`, `어`, `아`, `네네네`) 및 중복어(`아빠가 안 만들어줘서 아빠가 안 만들어줘서` → `아빠가 안 만들어주셔서`)를 자동 정제합니다.

- 변경 내역 표 (행 · 화자 · 이전 · 이후), 500건까지
